## 2. 已交付范围（有什么）

### 2.1 功能

- **网页后台**：登录；河长办公示牌 / 河道 / 水库；河长信息与变更；反馈列表与统计；用户 / 角色 / 菜单 / 部门 / 字典 / 地区；文件管理；参数配置；短信渠道与模板（交付为日志渠道）。
- **移动端 H5**：扫码看公示牌；群众短信登录与反馈；河长账号登录、审核分派、处理、核实。
- **后端模块**：`yz-server`、`yz-module-system`、`yz-module-infra`、`yz-water`（河长制相关）。

### 2.2 两套业务表都要保留（勿删其中一套）

系统里河道/公示牌等存在**两套表**，后缀不同、用途不同，交付库里**两套都要留**，删掉任一会导致另一端功能断：

| 表后缀 | 名称 | 谁在用 |
|---|---|---|
| `_bf` | 河长办备份表，如 `yz_signboard_bf`、`yz_river_channel_bf` | 手机扫码、后台「河长办」公示牌/河道/水库 |
| 无后缀 | 正式表，如 `yz_river_channel`、`yz_signboard`（正式牌本交付不主推） | 河长信息、河长变更、部分反馈关联等 |

河长人员只有一套：`yz_river_channel_management`（不分成 `_bf` / 正式两套人员表）。

## 3. 未交付名录（按需自行建设）

下列事项**不在本次交付包内**，对方若有需求，需自行采购、申请、对接或开发。均为**按需使用**，不影响本机用 dump + 日志短信把闭环跑通。

| 序号 | 未交付项 | 说明 |
|---|---|---|
| 1 | **短信对接** | 交付默认 `DEBUG_CONSOLE`（验证码/通知只打后端日志）。若要真发短信：自行前往第三方平台开户、接入 SDK、审核营业执照等，再在后台「短信渠道 / 模板」配置。 |
| 2 | **二维码业务落地** | 交付提供二维码**生成与配置能力**（参数里改 H5 前缀）。现场为每块设施/公示牌生成唯一码、打印张贴、按正式域名重新出码，由对方自行组织。 |
| 3 | **中间件 MinIO（对象存储）** | 交付默认文件进**数据库存储**，不依赖 MinIO。生产若要对象存储：自行安装 MinIO（或其它 S3 兼容服务），在「文件配置」切换主配置。 |
| 4 | **前端地理中间件 GeoServer** | 若地图要叠加 WMS 等：自行部署 GeoServer，按场景发布图层，并在移动端 `config.js`（或相关配置）填写服务地址。 |
| 5 | **域名、服务器、HTTPS 证书** | 自行申请或租用域名与服务器，配置 HTTPS。手机真机定位、对外扫码强烈建议 HTTPS；本机 `localhost` 仅适合桌面联调。 |
| 6 | **后期接入统一平台 / 免登录** | 若需与上级或第三方平台免登录打通：自行编写免登录/SSO 对接接口与安全策略，不在本精简交付范围内。 |
| 7 | **天地图、高德地图 Key** | 地图底图、定位逆地理等依赖第三方 Key。按需自行到天地图 / 高德开放平台申请，并替换移动端 `config.js`（及管理端相关配置）中的 Key；交付中的 Key 仅供联调参考，生产勿长期沿用。 |

## 5. 数据库如何交付与还原

### 5.1 dump 是什么

`yzwater_isolated_hezhangzhi-lite.dump` = PostgreSQL 自定义格式备份，内含**结构 + 数据**（含菜单收口、短信日志渠道、文件库存储、H5 地址默认 localhost 等）。

### 5.2 还原步骤

（软件已装好、PostGIS 可用的前提下）

```bash
createdb -h localhost -U postgres yzwater_delivery

psql -h localhost -U postgres -d yzwater_delivery -c "CREATE EXTENSION IF NOT EXISTS postgis;"

pg_restore -h localhost -U postgres -d yzwater_delivery --no-owner --no-acl \
  scripts/delivery/yzwater_isolated_hezhangzhi-lite.dump
```

抽查：

```bash
psql -h localhost -U postgres -d yzwater_delivery -c "SELECT count(*) FROM yz_signboard_bf;"
```

### 5.3 改后端连接

编辑 `yz-server/src/main/resources/application-dev.yaml`（当前启动命令使用 **dev**）：

- 库名改为 `yzwater_delivery`（或你实际库名）
- `username` / `password` 改为现场 PostgreSQL 账号  
- Redis 保持 `127.0.0.1:6379`

启动命令：

```bash
java -Dloader.path=lib -jar yz-server.jar --spring.profiles.active=dev
```

（须在含 `yz-server.jar` 与 `lib/` 的目录执行，一般是 `yz-server/target`。）

若改用 `--spring.profiles.active=local`，则改 `application-local.yaml`，不要混改。

## 6. 启动三端

先确保 PostgreSQL、Redis 已启动。

```bash
# 后端（首次需编译）
cd yzwater-mvp
mvn -pl yz-server -am package -DskipTests
cd yz-server/target
java -Dloader.path=lib -jar yz-server.jar --spring.profiles.active=dev

# 管理端（另开终端）
cd yz-ui/yz-boot-mini-front-master
npm install && npm run dev
# http://localhost:5173 ，VITE_BASE_URL 指向 http://localhost:48082

# 移动端（另开终端）
cd mobile-vue3-app
npm install && npm run dev
# http://localhost:3000/h5/
```

## 7. 交付后对方常改的配置（不必改业务代码）

管理端 **基础设施 → 配置管理**，或表 `infra_config`：

| config_key | 用途 | 交付默认 |
|---|---|---|
| `river_info_qr_code_address` | 河道信息码前缀 | `http://localhost:3000/h5/user_BaseInfo` |
| `river_issue_qr_code_address` | 公众反馈码前缀 | `http://localhost:3000/h5/login` |
| `h5_admin_login_qr_code_address` | 移动端后台登录 | `http://localhost:3000/h5/adminLogin` |
| `feedback_person_redirect_url` | 短链-反馈人 | `http://localhost:3000/h5/shortUrlDetail` |
| `handle_person_redirect_url` | 短链-处理人 | `http://localhost:3000/h5/adminLogin` |

前两个展示时会再拼 `?qrcode={公示牌标识}`；后台登录码不拼 qrcode。  
改域名后重新打开公示牌详情生成新码；**已打印旧码不会自动变**。

短信：交付为日志渠道；真发短信见上文「未交付名录」第 1 条。

文件：交付为数据库存储；MinIO 见未交付名录第 3 条。

## 8. 建议验收路径

1. 管理端登录 → 河长办公示牌 / 河道可查  
2. 公示牌详情三个二维码可显示  
3. 本机打开信息码 H5，公示牌详情正常  
4. 群众登录：验证码看**后端日志** → 提交反馈  
5. 河长端 `/h5/adminLogin` → 审核 / 处理 / 核实  
6. 管理端反馈列表能看到同一条

## 9. 联调注意（简要）

- **定位**：`https` 或 `localhost` 可用；手机 `http://局域网IP` 常被拒；失败时可用默认坐标继续演示。  
- **图片 URL**：默认 `http://localhost:48082/...`；本机后台可看；手机需能访问该地址。  
- **二维码默认 localhost**：只适合本机扫/本机浏览器；对外演示需改配置前缀。
